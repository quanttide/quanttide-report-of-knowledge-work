# ADR-0001: 凭证按「工作区 id + 名字」造号，落盘即锚定终身不变

状态：已接受
日期：2026-09-20

## 背景

工作流与步骤需要稳定的标识符：工单封面以 `workflow_id` 引用所引工作流，工作记录以 `step_id` 指认步骤，领域事件以二者去重，跨端对账以二者为主键。

v1 将凭证显式写入定义文件，由人工编制 UUID。该做法存在三个问题：

1. 凭证本身无语义，编制是纯维护负担；定义格式迁移时须批量补编，实验室 v1 至 v2 的迁移即以编造凭证为第一道工序。
2. 编制过程缺乏一致性约束：定义被复制后，副本与原件可携带同一凭证，形成两个事实共享一个身份。
3. 凭证落盘并纳入版本控制后，每次重新生成都会引入与内容无关的 diff。

初版决定以「读取时现算」化解上述负担，却把凭证与名字焊死：改名即换凭证，引用期身份只能靠「引用即冻结」守住——定义一经工单引用，连名字也不得再改。名字是可读的地址，地址需要随人更改；身份是锚，锚必须终身不变。二者混用，是现算模型的根本缺陷。

端云分工同样要求重新审视现算：端侧初始化（无云端参与的本地建区）必须能自行造号，uuid4 随机造号只有造号方知道，他端无法从既有事实重现同一凭证；而云侧对凭证的关切止于「是一枚合法 UUID」，不必实现派生算法。

## 术语

**凭证**：工作流、步骤、工单、工作记录的标识符，UUID。

**派生**：以确定性函数从既有事实计算凭证；同一输入在任意时刻、任意平台计算结果一致。

**造号**：为实体生成凭证。定义侧（工作流、步骤）按「工作区 id + 名字」以 uuid5 派生；工单与工作记录由程序生成 uuid4。

**锚定**：凭证首次落盘后成为该实体终身不变的标识；锚定后凭证与名字脱钩，改名不换凭证。

**登记处**：持有「名 → 号」绑定的一方——端侧为工作区聚合，云侧为工作流登记。

**uuid5**：RFC 4122 定义的第五版 UUID，输入为命名空间与名称，基于 SHA-1 计算；输出恒定，且符合 UUID 语法。

## 选项

选项一，人工显式编号：凭证写入定义文件。凭证与内容解耦、改名不换凭证；但编制是人工负担，复制场景下无重号约束，重新生成引入与内容无关的 diff。v1 即此。

选项二，按定义内容哈希：内容任一字节变化（包括勘误）即换凭证，在途工单的引用随之失效。凭证不稳定，不满足对账要求。

选项三，读取时现算：凭证不落盘，永远可由名字重算。新增与迁移零编制成本，任意一方可独立重算；但改名即换凭证，被迫以「引用即冻结」守住引用期身份，名字失去可改性。初版决定即此。

选项四，造号锚定：以 uuid5 派生自动造号，凭证首次落盘即锚定、终身不变。派生造号消除人工负担，落盘锚定消除改名换证；代价是重算验证退化为登记处比对，锚定后旧名随旧号占坑。

选择选项四。选项一是选项四在「人工造号」下的退化形，选项三是选项四在「不锚定」下的退化形。

## 决定

### 凭证算法

定义侧凭证采用 uuid5 派生造号。uuid4 随机造号无法被他端从既有事实重现，端侧初始化场景下跨端对不上；自定哈希截断则须自行定义输出格式与碰撞处理，uuid5 是 RFC 4122 的现成规范。工单与工作记录的凭证仍由程序在创建时生成 uuid4：二者是一次性事实，落盘即锚，与定义侧同遵「落盘即锚定」，差别只在造号手段。

### 造号输入

工作流凭证 = `uuid5(命名空间, "<工作区 id>/<工作流名>")`；步骤凭证 = `uuid5(命名空间, "<工作流凭证>/<步骤名>")`。

输入包含工作区 id，因为名字的作用域是单个工作区而非全局；不含工作区 id 会使两个工作区的同名工作流得到同一凭证，账目随之串号。步骤以工作流凭证为前缀分层派生，使凭证的层级与定义的结构层级同形：步骤名只须在工作流内唯一，且由步骤凭证可独立验证其所属工作流。拼接符 `/` 消除输入分段歧义。

### 锚定时机

凭证首次落盘即锚定——落在登记处、工单封面还是事件负载，效力相同。锚定之前，凭证只是名字的推论，改名即换推论，无引用受牵连；锚定之后，凭证终身不变，与名字脱钩。

### 名字变更

锚定后改名是身份中性操作：由登记处改绑「名 → 号」，凭证不动。封面按开单时的名与号存续——下游凭凭证直认，凭当时的名读；流水对账以凭证续账，不因改名中断。

改名须经登记处执行；绕过登记处改动定义的名字，装载核对时以「未登记定义」与「失配绑定」暴露，不静默生效。

锚定后旧名随旧号占坑：以旧名新建工作流，派生所得正是已锚定的旧凭证，登记处按主键判重即拒。区内名字因此只增不减。

### 云侧契约

云侧只验 UUID 格式与主键判重，不解释造号方式，不依赖派生算法与命名空间常量。幂等重放按主键判重消化，与流水「重放同 id 即拒」同一纪律。「同一输入在任意平台得同一凭证」是端侧之间（cli、studio）的互操作契约，由对账测试验证。

### 命名空间

命名空间为钉死的常量，定义于 `apps/qtcloud-work/src/cli/src/ids.rs` 的 `NAMESPACE`。变更命名空间不影响已锚定凭证，但使端侧重算自检与存量未锚定推论失效；跨端对表以同常量为前提，其变更必须另立 ADR。

### 引用与查填

工单封面所引 `workflow_id` 在开单时查填，落笔即封，封面同时存开单时的工作流名与凭证（双锚）。流水中的 `step_id` 由账本按 `step` 名查填，人工不写。核对以登记处比对为准；按名字重算仅在名字从未更名时与凭证一致，可作快速自检，不作判据。

### schema 约束

定义文件仍不含身份字段：「名 → 号」绑定由登记处持有，定义只承载内容。schema 校验拒绝 `id` 字段，防止定义内私造身份与登记处分叉。

## 影响

- 凭证终身不变：引用、事件、对账以凭证为主键，改名不换凭证、不断历史。
- 「引用即冻结」条款随本决定修订：工作流名的冻结废止，改名成为合法操作；定义内容（步骤、次序、指令）的冻结纪律不在本 ADR 范围，维持现状。
- 区内名字只增不减：旧名随旧号占坑，以旧名新建即撞号被拒。
- 重算验证退化为登记处比对：未更名定义仍可离线重算自验，更名后的核对依赖登记处。
- 定义文件不含身份字段：新增与迁移零编制成本；迁移时按「工作区 id + 名」自动批量造号，存量定义零改动读入。
- 各端（cli、studio）须实现同一 uuid5 算法并引用同一命名空间常量，跨端一致性由对账测试验证；云侧只验格式与判重。
- 步骤名在同一工作流内须唯一，这是造号输入的前提；现行校验未显式覆盖重复步骤名，列入补齐项。
